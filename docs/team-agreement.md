# Team Agreement - Team 22

Project: Department Course Timetable Management System (SENG 271)
Members: Arda AYDIN (@the-forward), Emre ÜNAL (@emreunalseng)

This file follows Section 7.1 of the SENG 271 Term Project Guide.

## 1. Communication
- Channel: face to face at the university, and WhatsApp between the meetings.
- We answer within 24 hours on weekdays.

## 2. Weekly meeting
- Day and time: every Friday at 19:00 (online).
- Length: 30 minutes.
- Agenda: what each member finished (shown running on their own computer), problems, the tasks and owners of the next week, and the deliverable that is due.
- We keep three lines of notes after every meeting (done, next, problems), so we can fill the contribution tables later.

## 3. Who edits which document
We work together on all parts. The table shows who starts a part; the other member reviews it.

| Part | Main responsibility | Reviewed by |
| --- | --- | --- |
| SRS and the requirement parts of the SDD | Arda | Emre |
| UML class diagram, flowchart and the design parts of the SDD | Emre | Arda |
| Code v1 (skeleton): the `io` package | Arda | Emre |
| Code v1 (skeleton): the `model`, `scheduling` and `ui` packages | Emre | Arda |
| Code v2 to Code v6 | split by feature at the weekly meeting | the other member |
| Checkpoint reports, test results and README | both | both |

The split of every code version is written in its release note. Each member writes code and documentation.

## 4. Code review before a version tag
- We pull before we start, commit small steps with clear messages and pull again before we push.
- Before a `code-vN` tag each member compiles and runs the other member's changes from the terminal and can explain them.
- We tag only after both members have run the program from the terminal.
- Tags are pushed one by one (`git push origin code-vN`).

## 5. If one member cannot work for a week
- Tell the partner as early as possible.
- Tell the instructor if a deliverable is affected.

## 6. AI tools
- We use AI tools only according to the instructor's guidelines and declare them in the AI-Use table of each document.
- We check everything they produce and never submit code or text that we cannot explain ourselves.
